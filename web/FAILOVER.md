# Автоматический резерв Qwen — Web 0.11

Основной диалог: Qwen3.5 9B на Windows через SSH-туннель (серверный `127.0.0.1:11435`). Резерв: уже установленный Qwen3.5 4B на сервере (`127.0.0.1:11434`). Обе модели используют одну SQLite-переписку и одну активную беседу. Ядро, память, обучение и настройки внутреннего голоса не изменяются.

## Настройки

`/home/ivan/deepbrain-web-data/dialogue.json`:

```json
{"provider":"ollama","model":"qwen3.5:9b-q4_K_M","fallbackEnabled":true}
```

`false` отключает резерв. Значение `{"provider":"openai"}` явно выбирает OpenAI; автоматического переключения на облако нет. Его ключ сохраняется.

## Поведение

- Доступен компьютер с моделью — выбирается 9B. Компьютер или модель недоступны — выбирается 4B. Если обе модели недоступны, показывается ошибка, история сохраняется.
- Проверка списков моделей не запускает генерацию; результат хранится до пяти секунд. После ошибки обращения к 9B действует пауза десять секунд перед возвратом. Исправный компьютер выбирается для следующего сообщения. Уже выполняющийся ответ 4B не отменяется.
- При обрыве обращения к 9B допускается одна попытка на 4B. Вычисление на компьютере могло завершиться до обрыва; в базе остаются одна пользовательская запись и один итоговый ответ. Диалог не имеет инструментов или действий с внешними последствиями. Некорректный или неполный ответ 9B не запускает дополнительную генерацию.
- Повтор идентификатора возвращает сохранённый результат. При перезапуске Web незавершённые запросы и попытки помечаются прерванными, не возобновляясь автоматически.
- Таблица `request_attempts` фиксирует попытки. У реплики сохраняются фактическая модель, место обработки, причина перехода и признак короткого ответа. Карточка сверху показывает модель для следующего сообщения; выполняющаяся реплика — фактическую модель текущего ответа.

## Нагрузка и контекст

4B использует контекст 4096 и удержание модели пять минут, как внутренний голос. Второй экземпляр Ollama не создаётся, его параллельность не меняется. Диалог обрабатывает одно сообщение за раз. Запрос может ждать внутреннего голоса; серверный CPU медленнее видеокарты. Тайм-аут 4B — 240 секунд, 9B — 120 секунд.

Ответ 4B ограничен 256 токенами. Если достигнут лимит, имеющийся текст сохраняется и отмечается в интерфейсе; можно попросить продолжить. В 9B передаются до шести недавних полных пар реплик (до 10000 символов истории), контекст — 16384. Для 4B выбирается меньше последних полных пар с консервативным пределом по UTF-8-байтам и резервом на шаблон и ответ. Слишком длинный текущий вопрос не обрезается: показывается просьба сократить его либо дождаться компьютера. При нехватке места снимок состояния помечается недоступным. Ограничивается только отправленный модели контекст; сохранённая переписка не удаляется.

Данные находятся в `/home/ivan/deepbrain-web-data/dialogue.sqlite3`, отдельно от памяти DeepBrain. В модель не передаются полные журналы или ключи; ответы модели не исполняются как команды. Начиная с Web 0.16/0.17, реплики пользователя дополнительно поступают в журнал опыта; смысловая оценка Qwen даёт ограниченное эмоциональное влияние, описанное в `../docs/semantic-appraisal.md`.

## Windows и откат

Действующий автозапуск `%LOCALAPPDATA%\DeepBrain\qwen_supervisor.py` и ограниченный ключ `~/.ssh/deepbrain-qwen-tunnel` продолжают работать. Ollama на Windows слушает loopback; облачные возможности отключены. После входа в Windows модель и туннель запускаются автоматически. Для резервного диалога компьютер не нужен, если работает сервер.

Обновление создаёт копию прежнего Web и резервные копии обеих SQLite-баз и настроек в `/home/ivan/deepbrain-runtime/upgrades/qwen-failover-*`. Перезапускается только Web. Миграция добавляет поля и таблицу, сохраняя исходные данные и беседу. Для возврата Web 0.10 также вернуть старый `dialogue.json` без нового поля. Добавленные поля совместимы со старым кодом; базу истории не откатывать поверх новых сообщений.

Протокол и очередь: [Ollama Chat API](https://docs.ollama.com/api/chat), [Ollama FAQ](https://docs.ollama.com/faq).
