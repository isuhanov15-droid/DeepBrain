# Диалог через OpenAI

Диалоговый адаптер добавляется к существующему Web. Ядро DeepBrain 1.10, ML и Ollama продолжают работу без перезапуска и изменения конфигурации. Подключение Яндекс Станции и доступ к существующим чатам ChatGPT в этот этап не входят.

## Первое подключение

В Web 0.10 сначала явно выбрать OpenAI: установить в `/home/ivan/deepbrain-web-data/dialogue.json` значение `{"provider":"openai"}`. Пока там выбран `ollama`, ключ OpenAI не используется для генерации и обращения остаются локальными. Автоматического переключения при недоступности Qwen нет.

1. Создать проект DeepBrain в https://platform.openai.com/, проверить оплату/кредиты проекта и создать API-ключ: https://platform.openai.com/api-keys.
2. В PuTTY выполнить `python3 /home/ivan/deepbrain-web-01/setup_openai.py` и вставить ключ при скрытом вводе. Ключ хранится только в `/home/ivan/.config/deepbrain/openai-api-key` с правами 600. Он не входит в Git, JSON-конфигурацию, браузер или резервную копию исходников. Пустой ввод сохраняет уже установленный ключ.
3. Обновить Web через Ctrl+F5, открыть «Диалог» и отправить первое сообщение. Наличие файла ключа ещё не означает, что аккаунт прошёл проверку: это выясняется по ответу API.

Официальные источники: [quickstart](https://developers.openai.com/api/docs/quickstart), [Responses API](https://developers.openai.com/api/docs/guides/text), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna).

## Настройки и данные

Необязательный файл `/home/ivan/deepbrain-web-data/openai.json`:

```json
{"enabled":true,"model":"gpt-5.6-luna","reasoningEffort":"low","maxOutputTokens":1024,"dailyRequests":100,"minIntervalSeconds":5}
```

Модель выбрана как экономичный начальный вариант по документации на 15.11.2026; доступность зависит от проекта. При отсутствии доступа нужно выбрать доступную модель. Автоматической замены на более дорогую модель нет. Для моделей без reasoning параметр `reasoningEffort` задаётся `null`.

OpenAI вызывается только при явной отправке сообщения: HTTPS `api.openai.com/v1/responses`, без перенаправлений, инструментов и автоматических повторов. `store=false` отключает сохранение Response для последующего получения через этот API; это не заявление о полном отсутствии хранения на стороне провайдера.

Передаются сообщение (до 4000 символов), не более шести последних успешных пар реплик (суммарно до 10000 символов) и белый список чисел/меток текущего состояния симуляции. Полные журналы, содержимое долговременной памяти, файлы, ключи и текстовые payload событий не включаются. Снимок старше 15 секунд обозначается как недоступный. Ответ модели считается разговором и не становится опытом агента или управляющей командой.

История, номера запросов и суточный счётчик сохраняются в `dialogue.sqlite3` отдельно от памяти агента. Учитываются и неуспешные попытки: при обрыве неизвестно, успел ли провайдер обработать запрос. День считается по UTC. Лимит числа запросов не является лимитом расходов в долларах. Повтор того же `requestId` возвращает сохранённый результат без обращения к OpenAI. После аварийного завершения незавершённый запрос получает статус неизвестного результата и не повторяется автоматически. «Новый диалог» меняет активную беседу, сохраняя прежние записи в базе.

Клиентские маршруты наследуют пароль Web и CSRF-защиту: `GET /web/dialogue`, `POST /web/dialogue/message`, `POST /web/dialogue/new`. Это интерфейс существующего Web, не публичный обработчик Алисы. Для будущей колонки понадобятся отдельная авторизация/привязка пользователя и адаптер её протокола.

## Проверки

`python3 -m unittest -v test_dialogue test_web_dialogue`

Тесты используют подменённый транспорт без внешних запросов: сохранение/восстановление истории, лимиты, повтор запросов, аварийное завершение, параллельные обращения, обработка Responses/refusal/incomplete, авторизация и CSRF, ограничение входа, сокрытие ключа и отсутствие записи в память DeepBrain.
