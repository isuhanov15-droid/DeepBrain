# Журнал изменений DeepBrain

## 1.4.0

### Добавлено

- Habit/Character v2 с атомарным сохранением в `memory/habits.v2.json` и поддержкой явного импорта старого снимка; по умолчанию импорт отключён.
- Раздельная статистика появления стимула, фактического выполнения привычного действия, положительных/отрицательных подкреплений и преимущества действия над фоном стимула.
- Защитные минимумы для дыхания при угрозе и разрыва петли, медленное затухание только неактивных привычек и защита от универсального доминирования `rest_short`.
- Команды `habit.status`, `habit.stats`, `habit.explain` и `character.status`.
- LLM Cortex v2 в роли внутреннего голоса: автоматическое наблюдение по интервалу и значимым переходам, контекст потребностей и активной привычки, связь с предыдущей мыслью и публикация принятой речи в обычный поток `LifeOutput`.
- Ограниченный журнал принятых размышлений `memory/inner-voice.jsonl`, команда `llm.journal` и HTTP-маршрут `GET /api/v1/llm/journal`.
- Фильтр минимальной уверенности LLM и отдельный счётчик отклонённых низкоуверенных ответов.
- Поля `reportSchemaVersion`, `runId`, `hostVersion` и `configVersion` в каждом новом отчёте эпизода, чтобы прогоны и версии больше не смешивались в аналитике.

### Исправлено

- Награда больше не приписывается привычке только потому, что присутствовал её стимул: обучение силы выполняется лишь после фактического routine-действия.
- Редкие контекстные привычки больше не затухают до нуля из-за глобального таймера, пока их стимул отсутствует.
- Социальный контакт и окно новизны имеют приоритет над умеренной усталостью; критическое истощение по-прежнему безопасно возвращает восстановление.

### Границы безопасности и совместимость

- Внутренний голос остаётся наблюдателем: он не выбирает действия, не обходит action mask и не пишет эпизодическую память.
- Старые конфигурации без секций `habits` и новых полей `llm` получают нормализованные значения по умолчанию.
- Основные поля Habit DTO сохранены; новая причинная статистика добавлена без удаления прежних полей.
- Повреждённое хранилище привычек резервируется, а запись выполняется через временный файл и атомарную замену.

## 1.3.0

### Добавлено

- Наблюдательный LLM Cortex с версионированным входным снимком и строгим JSON-контрактом ответа.
- Асинхронный клиент локальной Ollama для `qwen3.5:4b-q4_K_M`, одиночный запрос, тайм-аут, ограничение ответа и отбрасывание устаревшего результата.
- Команды `llm.status`, `llm.observe`, `llm.last` и события `cortex.insight`.
- Защищённый HTTP API v1 и поток SSE для мобильных клиентов, домашних ПК и внешних шлюзов.
- Универсальный конверт `deepbrain.external.v1` и интерфейс адаптеров для будущих MQTT, Home Assistant и ROS2.
- Проверка конфигурации запрещает не-loopback API без bearer token.
- Компактный семантический кадр Ollama без служебных идентификаторов и timestamp: состояние передаётся как короткие факты, события — без payload и полного JSON, память — как итог «что помогло/мешало» вместо диагностического отчёта.
- Наблюдаемость LLM-запросов: размер JSON, число символов полного prompt и полезных данных, токены prompt/output, времена загрузки и генерации Ollama, wall-clock latency и возраст кадра.

### Границы безопасности

- LLM остаётся наблюдателем: не выбирает действие, не вызывает исполнительный механизм, не обходит action mask и не пишет память напрямую.
- Внешний API v1 не предоставляет произвольных команд актуатора; удалённое исполнение потребует отдельного валидатора намерений и политики разрешений.
- LLM и внешний API по умолчанию отключены, поэтому старые конфигурации сохраняют прежнее поведение.
- Расширение `llm.status` и `llm.last` только добавляет поля; версия контракта `deepbrain.cortex.v1` не меняется.

## 1.2.0

### Добавлено

- Когнитивная долговременная память v2: похожие эпизоды объединяются в усиленные прототипы без потери числа представленных эпизодов.
- Защита от дубликатов, управляемое забывание старых малозначимых записей и защита повторяющегося либо критического опыта.
- Устойчивый опыт по сценариям с уверенностью, долей успеха и оценками того, какие действия помогали или мешали.
- Средняя награда по каждому действию в отчёте эпизода; память использует результат действия, а не только его частоту.
- Индекс сценария, настроения и квантованного состояния ограничивает recall заданным числом кандидатов даже при 5000 записях.
- Производный снимок опыта `memory/experience.json` и команды `memory.explain`, `memory.stats`, `memory.consolidate`.
- Трассировка recall содержит число индексированных кандидатов, полезное/вредное действие и уверенность.

### Совместимость

- Старые строки `memory/episodes.jsonl` версии 1 читаются без миграции; новые когнитивные поля являются необязательными.
- Старые `brainconfig.json` без настроек Memory v2 получают безопасные значения по умолчанию.
- Память по-прежнему влияет только на существующие разрешённые кандидаты и не обходит action mask.
- `memory/experience.json` является производным runtime-файлом и может быть восстановлен из `episodes.jsonl`.

## 1.1.1

### Исправлено

- Ответ `ml.train` теперь согласован с ML.Host и содержит признак фактического шага обучения, норму градиента и реальное заполнение replay-буфера.
- `mlstatus` больше не показывает фиктивное `буфер=0`, когда удалённый backend уже накопил переходы.
- Последний ненулевой loss сохраняется между интервалами обучения и не затирается холостыми вызовами `ml.train`.
- Ошибка, возвращённая самим ML.Host, отображается в диагностике remote backend.

### Совместимость

- Расширение ответа ML.Host обратно совместимо: прежние поля RPC сохранены, новые поля являются необязательными для старых клиентов.
- DeepBrain продолжает принимать ответы ML.Host версии 1.1.0; отсутствующая в старом ответе телеметрия получает безопасные нулевые значения.

## 1.1.0

### Добавлено

- Долговременная эпизодическая память с локальным ограниченным JSONL-хранилищем.
- Автоматическая загрузка воспоминаний при старте и безопасное пропускание повреждённых строк.
- Поиск похожих эпизодов по сценарию, настроению, боли, безопасности и возбуждению.
- Ограниченное влияние успешного и неуспешного прошлого опыта на оценки доступных действий.
- Затухание релевантности по времени, значимость воспоминаний и автоматическое уплотнение хранилища.
- Команды `memory.status`, `memory.recent` и `memory.search`.
- Трассировка `memory.store` и `memory.recall`.

### Исправлено

- Влияние угрозы на безопасность применяется только в момент появления события; одно событие больше не списывает `Safety` повторно на каждом тике своей заметности.
- Паническое завершение требует нескольких последовательных критических тиков, восстанавливает безопасное стартовое состояние и не может породить однокадровый каскад сбросов.
- При критически низкой безопасности политика принудительно получает исполнимое действие восстановления, даже при низком возбуждении или активном cooldown.
- Паническое завершение получает отдельный отрицательный `terminalPenalty`, поэтому аварийный переход не закрепляется положительной наградой за исследование.
- Причина `panic` имеет приоритет над частной причиной провала сценария.
- Проваленный сценарий больше не создаёт положительное смещение долговременной памяти, даже если его средняя локальная награда была положительной.
- Входящий `social_ping` теперь сам открывает социальное внимание и действие ответа, не завися от порога дефицита привязанности.
- Социальная награда и `socialSignalsSent` учитываются только после фактической обработки входящего сигнала, поэтому пустые исходящие сообщения не засчитываются как контакт.
- Remote ML checkpoint теперь использует один согласованный базовый путь, сообщает причину ошибки save/load и сразу восстанавливает число шагов обучения и вес политики.
- Старые checkpoint-файлы с цепочкой `.chk.net.net` продолжают загружаться и при следующем автоматическом сохранении мигрируют в формат `.chk` + `.chk.net`.

### Совместимость

- Память включается с безопасными значениями по умолчанию, даже если в старом `brainconfig.json` ещё нет секции `memory`.
- Существующие DTO и сетевой протокол не изменены.
- Каталог `memory/` является runtime-данными и не попадает в Git.
- Старые конфигурации без параметров `panicHoldTicks`, `panicRecoverySafety`, `panicRecoveryPainMax` и `panicTerminalPenalty` используют безопасные значения по умолчанию.

## 1.0.2

### Исправлено

- Полезное стабильное состояние больше не считается петлёй только из-за отсутствия изменения грубого снимка состояния.
- Для `stuck_state` требуется подтверждённое отсутствие прогресса и удвоенное окно наблюдения.
- Стратегия `focus` теперь создаёт исполнимые действия `focus_narrow` и `focus_widen`.
- ML выбирает только среди действий, которые одновременно присутствуют в кандидатах и разрешены маской.
- При исчерпании кандидатов создаётся набор безопасных recovery-действий вместо одного принудительного выбора.
- Вес загруженной ML-политики учитывает сохранённые шаги обучения, даже если replay-буфер после перезапуска пуст.
- Снижение ε начинается только после появления достаточного опыта.
- Режим оценки принудительно использует ε=0, даже если перед ним выполнялось обучение.
- Рабочую конфигурацию можно передать через `--config` или `DEEPBRAIN_CONFIG_PATH`; сборка больше не обязана перезаписывать её.
- `mlstatus` показывает режим, источник политики, буфер, шаги обучения, ε, вес сети, loss и понятные пустые диагностические поля.
- Разнообразие действий теперь считается по распределению действий, а не делится на длину эпизода; длинные сценарии больше не получают искусственно близкую к нулю оценку.
- `reports/` и `checkpoints/` исключены из Git.
- Добавлен совместимый с MSBuild 17.8 файл `DeepBrain.sln`.

### Добавлено

- Регрессионные тесты продуктивного стабильного состояния, подтверждения `stuck_state`, focus-стратегии, recovery-маски, ML-прогрева и выбора внешней конфигурации.
- Единая версия сборок `1.0.2`.

### Совместимость

- JSON-поля, DTO, TCP-команды и машинные идентификаторы не изменены.
- `DeepBrain.slnx` сохранён для более новых версий инструментов.
