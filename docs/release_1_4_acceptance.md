# DeepBrain 1.4 — release candidate 04, 2026-09-08

## Исправлено

- Обучение получает фактическое состояние и маску следующего решения. Раньше маска строилась отдельно от фильтра кандидатов выбора действия.
- Явно пустая маска не превращается во «все действия разрешены»; терминальный переход не продолжает оценку будущей награды.
- ML.Host получает seed и learningRate из конфигурации уже при первом inference.
- Абсолютный путь checkpoint больше не смешивает метаданные DeepBrain и ML.Host.
- Веса записываются новым поколением; указатель метаданных заменяется после записи весов. Старое поколение удаляется только после успешного переключения.
- Штатная остановка сохраняет ML и дожидается очереди отчётов. Сбой основного цикла завершает соседнюю задачу и возвращает ненулевой код.
- ml.reset действительно сбрасывает удалённую модель и replay. Несовместимые размерности не пересоздают модель молча.
- Нечисловые/несовместимые переходы отклоняются до помещения в replay.
- Нечитаемый существующий checkpoint блокирует новую инициализацию. При самостоятельном перезапуске ML.Host клиент приостанавливает обучение и сохранение: требуется остановить DeepBrain и возобновить пару через resume.sh. RPC обучения/сохранения проверяют идентификатор процесса ML.Host.

## Что проверено здесь

Полный присланный снимок: 426 файлов, 16 AXAML; явные ссылки на проекты и ресурсы разрешаются. Изменения ограничены файлами manifest.json.
Компиляция .NET 8 через Roslyn: Host, Shared, ML.Core, ML.Host и тестовые проекты.
109 тестовых случаев DeepBrain, 5 проверок сериализации/обучения, 18 новых приёмочных проверок — успешно.
Два отдельных процесса ML.Host и DeepBrain.Host: реальное TCP-обучение, штатный SIGINT, сохранение и восстановление trainSteps — успешно. Отдельный перезапуск ML.Host обнаружен; прежний checkpoint не изменён.
Это не полная проверка GUI: штатный MSBuild в среде проверки не запускается из-за ошибки чтения сведений о процессе. verify.sh на сервере собирает оба полных решения из новой копии без bin/obj, запускает dotnet test и отдельные приёмочные программы. Если любой шаг падает, запуск новых рабочих данных не выполняется.
Ollama здесь не запускалась. Проверка на сервере требует свежего принятого ответа и записи в новый журнал.

## Контракт восстановления и ограничения

Checkpoint сохраняет веса, число обновлений, epsilon и номер эпизода; метаданные ML указывают resumeMode=weights-only. Adam, replay, target-network history и полное состояние симулятора не сохраняются. При перезапуске replay/оптимизатор создаются заново, target получает сохранённые веса; это не побитово непрерывное обучение. Последний незавершённый переход не сохраняется. Внезапное отключение питания может потерять последние данные; это не заменяет резервное копирование.
Память, привычки и журнал имеют собственные файлы. Исправление часов привычек и схемы 3 из fix02 сохранено. Старые источники остаются в исходных каталогах и дополнительно архивируются. В новый запуск они не импортируются.
Новые привычки начинаются с заданных программой исходных правил/сил, без выдуманных наблюдений и счётчиков. Персона и конфигурация сохраняются. LLM остаётся предобученной Ollama; «с нуля» относится к опыту DeepBrain и его ML-политике, а не к весам языковой модели.
API остаётся на 127.0.0.1. Web Studio — следующий этап после 1.4; этот пакет не открывает интерфейс в сеть.

## Что означает закрытие 1.4

1. verify.sh завершился VERIFY PASSED на Ninkear (полные решения, тесты, приёмка).
2. Новый рабочий каталог создан один раз; origin.json фиксирует пустые хранилища, отсутствие импорта и хеши сборки/конфигурации. Обучение идёт в обычном DeepBrain.Host, не в Experiments.
3. status.py подтверждает рост тиков и trainSteps, отсутствие ошибок подсистем, новый завершённый эпизод в памяти и новый принятый ответ LLM в журнале. Пока это не выполнено, состояние WARMING UP/FAILED, не RELEASE CLOSED.
4. Остановка и восстановление проверены на реальных процессах здесь; приёмочный checkpoint round-trip повторяется серверными тестами. Для живой эпохи resume.sh возобновляет именно её данные.

Нельзя доказать отсутствие всех возможных дефектов. Эти критерии закрывают заявленные критические контракты 1.4; визуальная проверка desktop Studio и длительное наблюдение остаются эксплуатационными проверками.

## Полезность: отдельное доказательство

Пилоты fix03 не доказали превосходства нейросети: 11/36522 и 2/36494 изменений решения советником; около 70% решений имели лишь одно разрешённое действие. weight=0.6 не означает, что сеть меняет 60% решений. Малый разрыв Q после softmax и ограниченный набор кандидатов объясняют слабое влияние; это диагностический вывод, не доказательство оптимальности.
Исправленный переход меняет условия обучения: прежние пилоты нельзя считать оценкой этого релизного кода.
После накопления нового рабочего опыта сравнивать замороженную копию checkpoint с эвристикой на одинаковых сценариях и нескольких независимых seed. Отдельно сравнивать память/привычки включены и выключены при одинаковом исходном состоянии. Фиксировать награду, нарушения, циклы и изменения действий в одном состоянии. Замороженная оценка не обучает рабочие веса и не подменяет их.
Польза памяти в релизе проверяется как сохранение/поиск/влияние на решения, журнала — как сохранение принятого ответа; рост качества поведения требует отдельной сравнительной оценки. До неё не утверждаем «нейросеть лучше эвристики».
