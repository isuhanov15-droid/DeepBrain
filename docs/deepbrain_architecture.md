# Архитектура DeepBrain v1.3.0

## Обзор

DeepBrain v1.3.0 — детерминированное автономное ядро. Оно отвечает за моделирование мира, внутреннюю регуляцию, выбор действий, учёт эпизодов, когнитивную долговременную память и телеметрию. Studio работает в режиме наблюдения, а слои ML и LLM подключаются опционально через интерфейсы.

## LifeLoop

- `LifeLoop` — единственный оркестратор современного пути выполнения мозга.
- На каждом тике он читает текущий снимок конфигурации, продвигает суточное время и обновляет состояние мира, гомеостаз, оценку состояния, внимание, аффект, цели, планы, маски действий, выбор действия, награду, обучение, память и телеметрию.
- Цикл не зависит от Studio и взаимодействует с транспортом через делегаты.
- ML используется только через `IMlPolicyAdvisor`.

## EpisodeManager

- Отслеживает `episodeId`, `episodeTick`, длину эпизода и причину сброса.
- Завершает эпизод по лимиту времени, при петле, паническом состоянии или ручном сбросе.
- Запускает следующий эпизод без очистки личности, привычек и долговременной памяти.

## Память

- `EpisodeMemory` сохраняет недавний пошаговый опыт в RAM и обеспечивает кратковременное влияние.
- `SemanticMemory` агрегирует связь контекста, действия и награды в пределах текущего процесса.
- `PersistentEpisodicMemory` записывает итог завершённого эпизода в `memory/episodes.jsonl`, объединяет дубликаты и загружает память после перезапуска.
- Похожесть воспоминания учитывает сценарий, доминирующее настроение и близость боли, безопасности и возбуждения.
- Recall использует RAM-индекс сценария и квантованного состояния; файл не перечитывается и полный список не перебирается на каждом тике.
- Релевантность учитывает значимость, силу, повторяемость и давность эпизода.
- Консолидация объединяет близкие исходы, забывает старые слабые записи и формирует устойчивый опыт по сценариям в `memory/experience.json`.
- Результат каждого действия позволяет извлечь не только похожее событие, но и ответ «что тогда помогло».
- Влияние памяти ограничивается `memory.maxActionBias` и применяется только к уже допустимым кандидатам, поэтому память не обходит маски действий.
- Подробности формата и настройки описаны в `docs/memory.md`.

## RewardEngine

- На каждом тике формирует стабильное разложение награды:
  - `homeostasis`;
  - `explore`;
  - `social`;
  - `loopPenalty`;
  - `invalidActionPenalty`;
  - `total`.
- `RewardCalculator` — стабильная точка входа, используемая `LifeLoop`.
- Социальная составляющая начисляется только за подтверждённый ответ на ожидающий `social_ping`; сам факт исходящего сообщения без входящего контакта наградой не считается.

## Социальные события

- `social_ping` — входящее событие, а `Attachment` — дефицит социального присутствия; они намеренно не используются как взаимозаменяемые сигналы.
- Свежий входящий контакт независимо открывает социальный фокус и добавляет `emit_message` в кандидаты, но не обходит угрозу, маску безопасности или cooldown.
- После выбранного ответа событие атомарно помечается обработанным; только такой ответ увеличивает `socialSignalsSent` в отчёте эпизода.

## LoopDetector

- Обнаруживает непродуктивные повторяющиеся отпечатки состояния и чередующиеся последовательности `ABAB` в ограниченном окне.
- Стабильное состояние с положительной краткосрочной наградой не считается петлёй; для `stuck_state` требуется расширенное подтверждение отсутствия прогресса.
- Предоставляет силу петли, длину серии, тип петли и агрегированные счётчики.
- Передаёт штрафы в расчёт награды и механизм завершения эпизода.

## Сценарии и учебная программа

- `CurriculumManager` управляет активным сценарием и режимом продвижения.
- Сценарии задают параметры климата мира и вероятности событий, не изменяя основную логику.
- Режим учебной программы определяет момент переключения сценариев.

## Интеграция ML

- `IMlPolicyAdvisor` изолирует мозг от деталей реализации ML.
- Доступны backend-режимы `stub`, `local` и `remote`.
- Маски действий применяются до и после рекомендаций ML.
- Маска решения является пересечением разрешённых действий и реально созданных кандидатов, поэтому рекомендация ML всегда может быть исполнена без скрытой подмены.
- Вес сети прогревается по replay-буферу и сохранённым шагам обучения; ε не снижается до накопления минимального batch опыта.
- Режим оценки отключает обучение и сохраняет только телеметрию инференса.

## LLM Cortex

- `LlmCortexOrchestrator` получает редкие снимки `LifeStateDto` вне критического пути `LifeLoop`.
- `ILlmCortexClient` изолирует провайдера; первая реализация вызывает локальную Ollama.
- Перед Ollama внутренний снимок преобразуется в три короткие строки `state/events/memory` без служебных идентификаторов и времени. События содержат только тип, тяжесть, значимость и признак обработки; память содержит агрегаты recall и устойчивого опыта без доказательств эпизодов.
- Строгий контракт `deepbrain.cortex.v1` отклоняет лишние поля, некорректный JSON и устаревшие ответы.
- Статус и конверт результата содержат wall-clock latency, возраст кадра, размер запроса, число символов prompt/данных, токены и внутренние времена Ollama.
- Принятое наблюдение является телеметрией: оно не выбирает действие, не вызывает `Actuator` и не записывает память.
- Подробности приведены в `docs/llm_cortex.md`.

## Внешние устройства

- `ExternalEventHub` формирует универсальные события `deepbrain.external.v1` для состояния, вывода и Cortex.
- `ExternalApiServer` предоставляет HTTP-снимки и поток SSE для телефона или домашнего ПК.
- `IExternalOutputAdapter` является точкой расширения для MQTT, Home Assistant и ROS2 без изменения автономного ядра.
- Внешний API по умолчанию отключён; не-loopback привязка без bearer token блокируется.
- Подробности приведены в `docs/external_api.md`.

## Конфигурация Host

- По умолчанию используется `brainconfig.json` рядом с исполняемым файлом.
- Рабочий путь можно задать через `--config <path>` или `DEEPBRAIN_CONFIG_PATH`.
- Аргумент командной строки имеет приоритет над переменной окружения.
- Runtime-конфигурация, отчёты, checkpoints и файлы памяти не входят в исходный код релиза.

## Телеметрия

- `LifeStateDto` — стабильный контракт телеметрии для Studio.
- `Trace` содержит компактные технические строки и структурированные данные этапов.
- `Output` содержит только сообщения, сформированные мозгом.
- `Logs` содержит системные события, сообщения конфигурации и диагностику транспорта.

## Локализация

- Машинные контракты, JSON-поля и внутренние идентификаторы остаются английскими.
- `RussianDisplay` переводит известные идентификаторы только на границе отображения.
- Studio, консоль, журналы и компактная трассировка используют русский язык.
- Подробные правила описаны в `docs/localization.md`.

## Отчёты

- Завершённые эпизоды записываются в JSONL: `reports/episodes/YYYY-MM-DD/episodes.jsonl`.
- `PolicyEvaluator` оценивает качество эпизодов в скользящем окне для режимов обучения и оценки.
