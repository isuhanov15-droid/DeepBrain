# v1.4 fix03 — влияние сети на решения

Дополнение к clean_experiment_v14.md. Меняется только экспериментальный проект:
производственные правила выбора действий, награды, маски и обучение сохранены.

DiagnosticAdvisor оборачивает настоящий MlPolicyAdvisor. После Infer запоминаются
Q, после SelectAction — входной эвристический максимум, максимум Q среди разрешённых
действий и выбранное действие. После публикации LifeState фиксируется реально
выполненное действие. Наблюдение привязано к тому же тику: сон не наследует прошлую
диагностику. Веса, scores, результат SelectAction наблюдатель не изменяет.

В result.json / report.json:

- decisions — решения с полученными Q и хотя бы одним разрешённым действием;
- multiChoiceDecisions — решения, где разрешено хотя бы два действия;
- networkVsHeuristic — максимум Q не совпал с эвристическим максимумом;
- advisorVsHeuristic — результат смешанной политики не совпал с эвристическим
  максимумом на её входе в том же состоянии; при обучении здесь участвует epsilon;
- executedVsHeuristic — фактическое действие не совпало с тем же максимумом;
- postAdvisorChanges — действие изменилось между advisor и исполнением;
- meanQRange — среднее max(Q)-min(Q) по разрешённым действиям;
- meanTopTwoQGap — средняя разница двух лучших разрешённых Q;
- meanProbabilitySpread — средняя разница наибольшей и наименьшей вероятности
  после masked softmax по разрешённым действиям;
- meanMaxProbability — средняя максимальная вероятность, не оценка достоверности.

Последние четыре средних считаются по decisions. При единственном варианте gap,
range, spread равны нулю, maxProbability=1. Краткий summarize.py пересчитывает
средний gap только по multiChoiceDecisions; так отсутствие выбора не выглядит
как неспособность сети различать действия. При точных равенствах Q argmax зависит
от порядка действий: networkVsHeuristic без gap не доказывает сильное предпочтение.

В оценочных прогонах decisions.jsonl содержит каждое такое решение с исходными Q,
списком разрешённых действий, именами трёх выборов, epsilon и весом сети.
При обучении сохраняется выборка каждые 200 тиков; агрегаты охватывают все решения.
actions.txt сохраняет по одному фактически исполненному действию на тик, включая сон.

sequence в каждой паре сравнивает actions.txt: число отличающихся действий,
первый отличающийся тик, число тиков бодрствования в обеих ветках и различий в них.
После первого расхождения состояния могут различаться: sequence показывает
расхождение траекторий, а не причинное влияние сети в одном состоянии.

Увеличение бюджета: два независимых запуска с нуля, 24 000 и 120 000 тиков,
один снимок исходного конфига, одинаковые seed обучения=1337, сценарии и начальные
условия. Это сравнение бюджетов, не восстановление replay buffer/Adam из checkpoint.
Оба бюджета оцениваются при epsilon=0 и фиксированном NetWeightMax, каждый сценарий
по 2400 тиков для трёх world seed. Короткая оценка и один seed обучения ограничивают
обобщаемость результата; победа в одной паре не означает надёжное преимущество.

ScenarioTicks фиксирует фактически пройденные сценарии (включая сон), а не только
название начального сценария training. Никакая модель не переносится в рабочий Host.
